3. **多参数版本**（以3个参数为例）：
```csharp
   public delegate TResult Func<in T1, in T2, in T3, out TResult>(T1 arg1, T2 arg2, T3 arg3);
```

- **输入参数与返回类型**：所有`Func<>`委托的最后一个泛型参数为返回类型，其余为输入参数类型。例如，`Func<int, string, bool>`表示接受`int`和`string`参数并返回`bool`的方法。


1. **按位置傳參**：

- 不需要傳入 `null`，除非你明確想將參數值設為 `null`。

---

### **原因分析**
1. **NativeAOT与预编译查询的限制**
   EF Core的NativeAOT和预编译查询功能仍处于实验阶段，存在以下限制：
   - **仅支持原生类型**：查询中使用的常量值必须是`int`、`string`、`Guid`等原生类型。自定义类型（如`Id_Kv`）无法被静态分析，导致预编译失败。
   - **值转换器的限制**：即使通过`HasConversion`将`Id_Kv`映射为`BLOB`类型，NativeAOT的预编译过程仍无法处理自定义类型的常量表达式。

2. **错误直接原因**
   代码中`Po_Kv`实体使用`Id_Kv`作为主键类型，并在LINQ查询中作为常量值（例如`Where(p => p.Id  == idKv)`）。EF Core预编译时无法识别此自定义类型，抛出错误`System.NotSupportedException`。

---

### **解决方案**
#### 1. **暂时禁用NativeAOT和预编译查询**
由于功能尚不稳定，可先移除相关选项：
```bash

```
删除`--precompile-queries`和`--nativeaot`参数，避免触发实验性功能。

#### 2. **改用原生类型作为主键**

```csharp

```
若必须保留`Id_Kv`类型，需等待EF Core未来版本支持自定义类型预编译。

#### 3. **检查EF Core版本与配置**
- 确保使用EF Core 9+版本（NativeAOT支持从EF9开始实验性支持）。
- 项目文件中需启用拦截器命名空间（实验性功能需显式配置）：

#### 4. **避免动态查询**
预编译查询仅支持完全静态的LINQ表达式。动态查询（如拼接`Where`条件）需重构为静态表达式。
